# 车招雷达公众官网重塑设计规格

日期：2026-06-13  
状态：待用户书面评审  
设计方向：A「清爽科技求职平台」

## 1. 背景与目标

Vehicle Campus Hub 已具备公司、招聘项目、链接证据、日历和求职资料等基础能力，但当前界面更接近内部审计台账：

- 品牌使用 `VCH`、`EVIDENCE DOSSIER`、`SEARCH FIRST` 等内部术语，公众难以快速理解。
- 页面优先解释平台如何核验，而不是先回答学生“哪里能投、适合什么、下一步做什么”。
- 公司列表采用报表式横向结构，主按钮重复、视觉压迫，移动端页面过长。
- 深海军蓝、硬边框、等宽台账结构缺少现代求职产品的亲和力。
- 首页、公司库、详情页和日历反复展示相似来源说明，页面职责不清。

本次目标不是继续微调颜色和字号，而是把产品重塑为可面向公众长期使用的车辆行业校招官网：

1. 用户进入首页后 5 秒内理解产品用途。
2. 用户不打开外链也能判断当前机会、技术方向和可信程度。
3. 搜索、比较、判断、准备形成清楚的使用路径。
4. 手机端优先，组件边界可复用于后续小程序和 App。
5. 保留现有真实公司与证据，不为丰富页面编造招聘信息。

## 2. 品牌与产品定位

### 2.1 品牌

- 中文主品牌：**车招雷达**
- 英文副名：**Vehicle Campus Hub**
- 产品定位：**2027 届车辆行业校招信息平台**
- 首页核心标题：**更快找到适合你的车企机会**
- 核心说明：**聚合车企、新势力、自动驾驶、三电与零部件企业的官方入口、招聘进度和技术方向，帮你少翻群聊，多做准备。**

品牌不使用 `VCH` 作为公众主标识。英文名称只作为辅助识别和工程仓库名称保留。

### 2.2 目标用户

- 车辆工程、机械工程、自动化、控制方向学生。
- 自动驾驶、嵌入式、车载软件、智能座舱方向学生。
- 三电、电池、热管理、底盘与测试验证方向学生。
- 主要面向 2027 届本科、硕士和博士毕业生。

### 2.3 产品人格

- 清楚，不卖弄内部术语。
- 可靠，但不把严肃等同于沉重。
- 友好，不使用过度营销或社区黑话。
- 高效，让用户快速找到下一步。
- 克制，只展示有依据的信息。

## 3. 核心产品原则

1. **机会优先，证据托底。** 用户先看到可以做什么，再看到判断依据。
2. **具体项目和通用入口分层。** 招聘官网存在不代表 2027 届项目已开放。
3. **没有可靠日期就不显示精确日期。**
4. **没有具体岗位来源就不生成虚假岗位卡片。**
5. **一家公司最多一个主操作。** 其他来源进入次级区域。
6. **一个信息只在最合适的页面重点说明一次。**
7. **移动端优先。** 桌面增强信息密度，但不改变用户路径。
8. **状态文案面向学生。** 避免 `证据档案`、`决策摘要`、`情报库` 等内部表达。

## 4. 全站信息架构

| 页面                         | 用户问题                             | 页面职责 |
| ---------------------------- | ------------------------------------ | -------- |
| 首页 `/`                     | 最近有哪些值得关注的机会？           | 发现     |
| 公司机会 `/companies`        | 哪些公司适合我，现在哪里能投？       | 比较     |
| 公司详情 `/companies/[slug]` | 这家公司现在能不能投，适合什么方向？ | 判断     |
| 招聘日历 `/calendar`         | 什么时候需要行动？                   | 时机     |
| 求职指南 `/resources`        | 笔试、面试和简历怎么准备？           | 准备     |
| 关于我们 `/about`            | 这个平台为什么值得信任？             | 建立信任 |

公开导航使用：

- 首页
- 公司机会
- 招聘日历
- 求职指南
- 关于我们
- 反馈信息

生产环境不显示后台入口。

## 5. 首页设计

### 5.1 页面顺序

1. 顶部导航。
2. Hero 与全局搜索。
3. 一组真实数据概览。
4. 现在值得关注的机会。
5. 最近变化与新手引导。
6. 按技术方向找机会。
7. 平台核验说明。
8. 页脚。

### 5.2 Hero

- Eyebrow：`2027 届车辆行业校招`
- H1：`更快找到适合你的车企机会`
- 搜索框支持公司、技术方向和城市。
- 快捷方向：自动驾驶、嵌入式、三电、底盘、热管理。
- 桌面端右侧使用抽象雷达图形和一条真实最新更新。
- 移动端删除大型雷达装饰，搜索保持首屏核心操作。

### 5.3 数据概览

只显示一组可解释的真实数据：

- 已收录企业。
- 可用官方招聘入口。
- 明确 2027 届项目。
- 最近一次数据更新。

不得把通用招聘入口计入明确开放项目。

### 5.4 机会卡片

首页桌面最多 3 家重点机会，移动端最多 3 家，不渲染完整公司列表。每张卡片包含：

- 公司名、类型与城市。
- 当前 2027 届状态。
- 项目名称。
- 主要技术方向。
- 最后核验日期。
- 一个明确主操作。

## 6. 公司机会页设计

### 6.1 搜索与筛选

默认显示：

- 搜索。
- 届次。
- 公司类型。
- 技术方向。
- 排序。

城市、链接状态和更多条件收进“更多筛选”。默认排序：

1. 明确开放项目。
2. 最近核验时间。
3. 公司名。

### 6.2 列表

桌面采用宽松的情报列表，移动端改为单列卡片。固定信息顺序：

1. 公司身份：名称、类型、城市。
2. 当前状态与技术方向。
3. 当前项目或入口说明。
4. 最后核验日期。
5. 一个外部主操作和一个内部详情入口。

公开文案示例：

- `2027 项目已开放`
- `等待 2027 项目`
- `信息待确认`
- `查看官方项目`
- `打开校园招聘门户`
- `入口暂不可用`
- `了解公司机会`

不再使用 `查看证据档案`。

## 7. 公司详情页设计

### 7.1 顶部

突出：

- 公司名、类型、城市和技术方向。
- 2027 届状态。
- 官方入口状态。
- 最后核验日期。
- 唯一主操作。

### 7.2 主体

主栏：

1. 当前校招机会。
2. 适合关注的技术方向。
3. 官方来源与核验记录。
4. 常见问题或求职指南关联。

侧栏：

- `现在可以做什么？` 快速回答。
- 信息反馈入口。

移动端把快速回答移动到公司标题下方，侧栏自然下沉。

### 7.3 可信度表达

可信度通过正常产品语言表达：

- `页面明确面向 2027 届`
- `官方校园招聘门户`
- `最后核验 6 月 11 日`
- `旧链接已失效，不再作为投递入口`
- `企业官网仅用于了解业务`

不使用无法解释的数字匹配分数。

## 8. 招聘日历设计

页面分为：

1. 7 天内截止。
2. 30 天内截止。
3. 本月新开启。
4. 已确认的招聘节点。
5. 已开放但未公布截止日期。
6. 企业观察名单入口。

规则：

- 只有可靠来源和明确日期的事件进入时间线。
- 同一事件只出现一次。
- 没有可靠日期时显示清楚空状态。
- 未公布截止日期的项目以项目卡片展示，不伪造日期。
- 尚未发布项目的企业不逐条重复外部按钮，仅提供紧凑观察名单入口。

## 9. 求职指南设计

公开名称从“笔试面经资料库”调整为“车辆行业求职指南”。

页面结构：

1. 搜索和类型筛选。
2. 一篇入门路线图。
3. 三篇重点指南。
4. 按技术方向排列的完整文章。

方向包括：

- 自动驾驶。
- 嵌入式与车载软件。
- 底盘与车辆动力学。
- 整车研发。
- 三电、电池与热管理。
- 智能座舱。
- 测试验证。
- 简历与通用面试。

每个资源必须有完整正文页、目录或实际内容。一句简介不构成资源。平台原创内容标记为“平台整理”，不标记为“待核实”。

## 10. 关于与反馈

关于页使用公众语言说明：

- 我们为谁服务。
- 我们整理什么。
- 我们如何判断信息。
- 我们不会做什么。
- 如何提交信息反馈。
- 免责声明。
- 后续小程序和 App 方向。

反馈入口必须真实可用。第一版继续使用 GitHub Issue 预设模板，并在按钮旁解释需要提交的内容。

## 11. 视觉系统

### 11.1 方向

清爽、明亮、现代的科技求职平台。参考：

- Simplify 的搜索效率和筛选层级。
- Notion Careers 的留白与分组。
- Porsche Careers 的克制和单一核心行动。
- Bosch Careers 的学生阶段表达。
- 国内校招产品的城市、届次和方向语义。

不复制对方代码、图片、商标或完整布局。

### 11.2 颜色

- 主蓝：`#215EE8`
- 深蓝：`#1748BD`
- 正文：`#12203A`
- 次级文字：`#68758C`
- 页面背景：`#FBFCFF`
- 浅蓝背景：`#F5F8FF`
- 分隔线：`#E2E8F2`
- 开放状态：`#0D9768`
- 待确认状态：`#D98224`
- 失效状态：仅在风险信息中使用红色。

### 11.3 字体与尺寸

中文优先使用可稳定加载的现代中文字体栈，避免依赖 Windows 专属字体。若引入网络字体，必须有本地回退且不阻塞首屏。

- 桌面 H1：48–64px。
- 移动 H1：30–36px。
- 页面标题：32–40px。
- 卡片标题：18–22px。
- 正文：16px。
- 辅助信息：13–14px，不低于可读下限。

### 11.4 形状与动效

- 圆角 10–20px，按层级统一。
- 阴影轻量，只用于浮层、搜索和重点卡片。
- 使用抽象雷达、轨迹和车辆技术节点建立行业识别，不依赖车企品牌图片。
- 动效限制在首屏进入、hover、focus 和状态变化。
- 尊重 `prefers-reduced-motion`。

## 12. 组件边界

计划形成以下可复用组件：

- `SiteHeader`
- `SiteFooter`
- `BrandMark`
- `GlobalSearch`
- `FilterBar`
- `MetricCard`
- `OpportunityCard`
- `CompanyListItem`
- `CompanyStatus`
- `SourceMeta`
- `PrimaryLinkAction`
- `UpdateFeed`
- `DirectionCard`
- `EmptyState`
- `FeedbackCallout`
- `PageHero`

组件只接收序列化后的展示模型，不直接访问 Prisma。页面数据转换集中在服务端数据层，便于未来复用于 API、小程序和 App。

## 13. 数据与错误状态

- 保留现有 Company、CompanyLink、Recruitment、Resource 等数据。
- 不因缺少来源删除公司。
- 不新增虚构公司、岗位、日期或链接。
- 无来源或无效链接显示明确禁用状态。
- API 或数据库错误显示友好重试提示，不白屏。
- 空列表说明原因并提供清除筛选或返回全部公司的操作。
- `example.com`、`#`、空地址和非法 URL 永远不渲染为可点击外链。

## 14. 响应式与可访问性

验收视口：

- iPhone SE：375px。
- iPhone 14：390px。
- iPad：820px。
- Desktop：1440px。

要求：

- 无横向滚动。
- 主要操作热区至少 44px。
- 所有输入、选择器、菜单和按钮具有可访问名称。
- 键盘焦点顺序符合视觉顺序。
- `focus-visible` 清晰。
- 色彩不是状态的唯一表达。
- 标题层级唯一且连续。
- 移动端不保留桌面多列报表。

## 15. 测试与视觉验收

自动化覆盖：

1. 六个公开页面正常打开。
2. 首页和移动端展示数量限制。
3. 搜索、筛选、排序和清除筛选。
4. 公司主操作名称具体且同 URL 不重复。
5. 日历无重复事件和虚假精确日期。
6. 资源均能进入完整正文。
7. `/admin` 生产环境保持 404。
8. 无空链接、占位链接和失效主按钮。
9. 四种视口无横向滚动。
10. 无 hydration、page error、严重 console error 和关键请求失败。
11. 主要交互热区和可访问名称。

视觉验收：

- 为首页、公司库、公司详情、日历、求职指南和关于页保存桌面及移动端截图。
- 对照本设计规格检查层级、留白、文案和操作优先级。
- 发现拥挤、重复、错位或公众语义不清时直接修复。

## 16. 版本与迭代记录

本轮作为一个新的兼容功能版本发布，目标版本为 `v2.3.0`，最终版本由 Release Please 根据实际提交生成。

需要更新：

- `CHANGELOG.md`
- `REDESIGN_REPORT.md`
- `TEST_REPORT.md`
- 新增本规格文档。
- 新增重构前后截图目录。
- Git commit、PR、Vercel Deployment 和部署标签保持一致。

每个阶段采用 Conventional Commits，并通过受保护的 `main`、CI、Vercel Preview 和生产 smoke 后发布。

## 17. 非目标

本轮不做：

- 用户登录、收藏和投递进度。
- 会员或付费功能。
- 企业自助后台。
- AI 简历匹配。
- 大规模补充未经核验的企业数据。
- 微信小程序和 App 实现。

这些能力可在公众官网视觉与信息架构稳定后继续规划。
